# Trazaloop v1.0.0 · Smoke tests manuales

Validación **manual** posterior al primer deployment de producción.
Se ejecuta contra el dominio definitivo, con datos reales.

> **Alcance Ruta A.** Todas las secciones corresponden a funciones
> **incluidas** en v1.0.0 (`V1.0.0_ROUTE_A_SCOPE.md`).
>
> **No se prueba nada de lo aplazado**, porque no existe en el código:
> pagos y Mercado Pago · renovación automática · avisos automáticos de
> renovación · Google Analytics 4 · Google Tag Manager · cookies opcionales
> y banner · consentimiento y correos de mercadeo · preferencias de
> comunicaciones · exportación integral automatizada · eliminación
> automatizada.
>
> Si alguna de esas funciones apareciera en la interfaz, es un **defecto**:
> el alcance no las incluye.

> ⚠️ **Prohibido en producción**: `npm run test:rls`, `npm run seed:demo`,
> las suites de `tests/rls/*`, las suites adversariales y
> `npm run cleanup:staging`. Todas crean o borran datos.
>
> Las únicas verificaciones automatizadas aptas para producción son de
> solo lectura: `npm run verify:prod` y
> `scripts/release/v1/verify-empty-production.sql`.

**Cómo usar este documento:** marca cada casilla. Cualquier ❌ es NO-GO
hasta resolverlo. Anota el resultado real cuando no coincida con lo
esperado.

Cuentas necesarias:

| Rol | Para qué |
|---|---|
| **SUPER** | Superadministrador oficial (`platform_staff`) |
| **A-ADMIN** | Admin de la empresa de prueba A |
| **A-VIEWER** | Rol de solo lectura en la empresa A |
| **B-ADMIN** | Admin de una segunda empresa B (aislamiento) |

### 4.1 Activación manual de Full / Extra (Ruta A)

En v1.0.0 **no hay pagos dentro del software**: la contratación y la
facturación ocurren fuera de Trazaloop y la activación la hace el
superadministrador.

- [ ] SUPER cambia el acceso de una empresa a **Full** y el cambio surte
      efecto de inmediato.
- [ ] Lo mismo con **Extra**; la diferencia observable es la **cuota de
      almacenamiento**, no las funcionalidades.
- [ ] La interfaz **no ofrece** ningún flujo de pago, checkout, tarjeta ni
      pasarela.
- [ ] La interfaz **no promete** renovación automática ni avisos
      automáticos de renovación.
- [ ] Al vencer un acceso Demo, el módulo se bloquea y la reactivación
      requiere la intervención del superadministrador.

## 19.1 Ausencia de lo aplazado (Ruta A)

Verificación de que **nada de lo aplazado se coló** en la versión.
Cualquier casilla que falle es un defecto de alcance.

**Analítica y cookies** — con las herramientas de desarrollo abiertas:

- [ ] La pestaña de **red** no muestra ninguna petición a
      `google-analytics.com`, `googletagmanager.com` ni dominios de
      analítica.
- [ ] La consola no expone `window.gtag` ni `window.dataLayer`.
- [ ] Las únicas cookies presentes son las **técnicas necesarias**:
      `tz-active-org` y las de sesión de Supabase Auth.
- [ ] **No aparece banner de cookies** — correcto: no hay cookies
      opcionales en v1.0.0.

**Pagos y mercadeo:**

- [ ] No existe ninguna pantalla de pago, checkout ni pasarela.
- [ ] No aparece Mercado Pago en ninguna parte de la interfaz.
- [ ] No hay casilla de consentimiento de mercadeo en el registro.
- [ ] No hay pantalla de preferencias de comunicaciones.
- [ ] Ningún texto promete renovación automática ni avisos automáticos de
      renovación.

**Datos:**

- [ ] No se ofrece «eliminar mi cuenta» automatizado *(en v1.0.0 el
      procedimiento es manual)*.
- [ ] No se ofrece exportación integral automatizada *(existen las
      exportaciones CSV funcionales de maestro de documentos y matriz de
      evidencias, que sí son parte del alcance)*.

- [ ] Buscando `SUPABASE_SECRET` y `service_role` en el código fuente

- **No se inventa ninguna cláusula nueva.**
- **No se elimina ninguna obligación, derecho ni descargo existente.**
- Se retira **solo** el encuadre de «versión preliminar / beta /
  lanzamiento controlado».
- Se **conserva el efecto jurídico** de la cláusula de actualización (el
  documento puede cambiar y se exigirá nueva aceptación); lo único que
  desaparece es la referencia a un «lanzamiento definitivo» futuro, que

- La ampliación de alcance a Textiles en la cláusula 1 **sí es un cambio

## 4. Procedimiento (NO ejecutado)

Script: **`scripts/release/v1/publish-legal-v2.sql`**

Garantías del script:

1. **Transaccional.** Todo ocurre dentro de un único `BEGIN … COMMIT`: o se
   publican ambos documentos y se archivan ambos v1, o no cambia nada.
2. **Falla si el estado no es el esperado.** Aborta si no encuentra
   exactamente un `terms/v1` activo y un `privacy/v1` activo con el
   contenido preliminar conocido.
3. **Idempotente.** Si `v2` ya existe y está activo, no hace nada y lo
   informa.
4. **No borra historial.** `v1` pasa a `status = 'archived'`; nunca se
   elimina. Las aceptaciones en `user_legal_acceptances` apuntan al `id`
   del documento y siguen siendo válidas como registro histórico.
5. **No toca la migración `0066`** ni crea una `0103`.

Ejecución (solo tras aprobación legal):

```bash
# 1. Copia de seguridad de la tabla ANTES de tocar nada
pg_dump "$SUPABASE_DB_URL" -t public.legal_documents \
        -t public.user_legal_acceptances -f legal_backup_pre_v2.sql

# 2. Ensayo: leer el script completo y confirmar el texto con el área legal
#    (no hay dry-run posible en SQL puro; el ensayo es la lectura humana)

# 3. Ejecución, solo con ON_ERROR_STOP
psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 \
     -f scripts/release/v1/publish-legal-v2.sql
```

## 5. Riesgos e instrucciones para revisión humana

| Id | Riesgo | Tratamiento |
|---|---|---|
| **L-1** | Publicar `v2` obliga a **todos** los usuarios existentes a volver a aceptar en `/legal/accept` antes de seguir usando la plataforma. | Es el comportamiento diseñado y correcto. Debe anunciarse. En una producción **recién creada y sin empresas** el impacto es nulo — por eso conviene publicar `v2` **antes** de dar de alta a la primera empresa. |
| **L-2** | La ampliación de la cláusula 1 a Textiles es un **cambio sustantivo de alcance**, no una limpieza de lenguaje. | **Decisión del responsable legal.** Si prefiere no ampliar el alcance ahora, elimine esa parte del script y publique `v2` solo con la retirada del lenguaje preliminar. El script está comentado para permitirlo. |
| **L-3** | El texto legal no está escrito por un abogado. | El informe no lo corrige: solo señala el problema. **Revisión legal obligatoria antes de producción.** |
| **L-4** | Si se ejecuta en staging y en producción por separado, las versiones pueden divergir. | Ejecutar el mismo script en ambos, y verificar con la sección 3d de `verify-empty-production.sql`. |
